# Статический анализ исходного кода

## Цель

В соответствии с **ГОСТ Р 56939-2024** статический анализ исходного кода направлен на предотвращение внесения потенциально опасных конструкций и ошибок в ПО, а также выявление опасных конструкций и уязвимостей из заимствованного кода.

## Инструмент статического анализа

В проекте используется **golangci-lint v2.12.1** — мета-линтер для языка Go, агрегирующий набор специализированных анализаторов.

**Установка:**
```bash
curl -sSfL https://golangci-lint.run/install.sh | sh -s -- -b $(go env GOPATH)/bin v2.12.1
```

**Запуск:**
```bash
make lint
```

## Компоненты анализатора

Инструмент объединяет следующие категории проверок:

| Категория | Линтеры | Назначение |
|-----------|---------|------------|
| Безопасность | `gosec` | Выявление уязвимостей (SQL-инъекции,硬код credentials, небезопасное использование unsafe) |
| Обработка ошибок | `errcheck`, `errorlint`, `nilerr` | Контроль обработки ошибок, корректное форматирование сообщений |
| Качество кода | `gocritic`, `staticcheck` | Семантический анализ, выявление избыточных конструкций, неиспользуемого кода |
| Стиль оформления | `revive` | Проверка именования, форматирования комментариев, структуры экспортируемых типов |
| Производительность | `bodyclose` | Контроль закрытия HTTP-тел, предотвращение утечек ресурсов |


## Перечень инструментов

| Инструмент | Версия | Назначение |

## Конфигурация

Параметры настройки зафиксированы в файле `.golangci.yml` и включают:

- **Список линтеров**
- **Исключения**: тестовые файлы `_test.go`
- **Правила обработки ошибок**: исключение отладочных вызовов `logrus.Debug*` из проверки `errcheck`
- **Проверки безопасности**: отключен код G104 (избыточные проверки ошибок)
- **Требования к стилю**: запрет blank-imports вне main/test, проверка заглавных букв в сообщениях ошибок
- и др.

На примере данного проекта конфигурация обеспечивает выявление уязвимостей:
- SQL-инъекций (`G201`)
- Необработанных ошибок (`errcheck`)
- Stuttering в именах типов (`revive/exported`)
- Неиспользуемых полей (`unused`)

## Отчеты по результатам

Формат вывода — консольный (текстовый) с указанием:
- Файла и строки кода
- Типа нарушения (имя линтера)
- Краткого описания проблемы

**Пример отчета:**
```text
internal/repository/severities/createSeverity.go:12:11: G201: SQL string formatting (gosec)
internal/handler/handler.go:48:2: field services is unused (unused)
```
