# Фаззинг тестирование методом мутации данных

## Цель

В соответствии с **ГОСТ Р 56939-2024** фаззинг-тестирование программы: Вид работ по исследованию программы, основанный
на передаче программе случайных или специально сформированных входных данных, отличных от
данных, предусмотренных алгоритмом работы программы.

Для реализации фаззинг-теста в Go разработчик создает `seed`. `Seed` - в контексте фаззинг-тестирования это
эталонный набор входных данных, предоставленный разработчиком, который служит исходным материалом
для генерации всех последующих мутаций. Фаззер не генерирует данные «с нуля» - он видоизменяет существующие `seed'ы`.
При
запуске командой
`go test -fuzz` фаззер сначала прогоняет каждый seed через тестируемую функцию, формируя базовую карту покрытия кода.
Затем он создает параллельные воркеры (обычно по числу ядер CPU), каждый из которых независимо мутирует seed: применяет
бит-флиппинг, вставку, удаление, дублирование байтов и другие преобразования. Мутировавший вход подается в функцию, и
фаззер проверяет, затронул ли он новые строки кода. Если да - входные данные сохраняются как `«интересные»` и становятся
основой для следующих мутаций; если нет - отбрасываются. Цикл продолжается заданное время (например, 30 секунд). Фаззер
завершается с ошибкой (тест считается проваленным) в случаях:

- возникновение паники (`panic`)
- вызове `t.Fatalf/t.Errorf`
- таймауте

В остальных случаях тест считается успешным.

## Инструмент фаззинг-тестирования

В проекте используется стандартный пакет **testing**, который в стандартной спецификации включает в себя утилиту для
работы с
фаззинг-тестами `-fuzz`.

В проекте реализован пример фаззинг-теста:
- **Тестируемая функция**: пакетная функция 'Parse' `pkg/parser/parser.go`
- **Реализация фаззинг-теста**: тестирование пакетной функции 'Parse' `pkg/parser/parser_test.go`

**Запуск:**

В общем случае запуск фаззинг-тестирования выполняется следующим образом

```bash
go test -fuzz=FuzzИмяФункции -fuzztime=30s
```

Для удобства запуска фаззинг-тестов в `Makefile` реализована цель `fuzz-all`. 
Для запуска фаззинг-тестирования в корне проекта необходимо выполнить:

```shell
make fuzz-all
```

## Отчеты по результатам

Формат вывода - консольный (текстовый) с указанием:

- Файла и строки кода
- Типа нарушения (тип ошибки)
- Краткого описания проблемы
